design-language/components.md

Components

Working agreement

Before any specialised component is built, the design intent must be defined and logged here.

The question is always: what problem is this component solving?

The answer gets logged in the Tier 2 table before building starts. This is a one-question check — it doesn't block the build, it just ensures the rationale isn't lost.

Base components (Tier 1) are exempt — they follow established conventions and only need rationale logged when we deliberately diverge.

Component taxonomy

There are two tiers of component in this library. Understanding which tier a component belongs to determines how it should be designed, documented, and used.

Tier 1 — Base components (src/primitives/)

Standard UI controls that map directly to established web patterns. These are atoms — single-responsibility, stateless where possible, and not specific to LawAdvisor's product logic.

Rationale approach: These follow established conventions. Use component.gallery as the reference for intended behaviour. No product-specific rationale needed unless we deliberately diverge from convention.

la-activity-item

A single event row in a chronological activity feed — icon circle, a vertical connector line to the next item, a body slot for the event description (may contain inline <a> links), and a timestamp. Compose multiple items in any container; the connector lines chain them into a timeline. Set last on the final item to suppress its connector. Presentational — no events. Used in the per-investor Activity tab (Sprint 12).

Props: time (timestamp string), last (boolean — suppresses connector on the final item) Slots: default (event text), icon (Phosphor <i> inside the circle) Events: none — presentational only

la-avatar

Initials avatar for people and entities. Derives two-letter initials automatically from name (first letter of the first two words), with an initials override for entities or edge cases. Three fixed sizes — sm (32px), md (40px), lg (48px) — map to product contexts (compact lists / person rows / detail headers). Purely presentational and decorative (aria-hidden); the adjacent visible name carries the accessible identity. Used across investor surfaces (Sprint 12) and the share modal.

Props: name (auto-derives initials), initials (override), size ('sm' | 'md' | 'lg', default md) Slots: none · Events: none

la-badge

A small inline primitive with two types. Badge (pill) communicates status, category, or severity at a glance; always paired with content, never standalone. Counter (circle) communicates a numerical count — unread items, queue depth, notification totals.

Types: badge (default), counter Variants: danger, warning, success, neutral, info, accent, primary Appearance: filled (default), ghost, dot (badge type only, below). For badges, use ghost for inert status tags; for counters, it provides the tinted numerical treatment.

Filled badge chrome is shared across variants — all non-primary filled badge variants use --la-color-bg-subtle with a 1px --la-color-border-light border. Use this appearance only when the bordered chip treatment has a clear semantic purpose. Inert status tags use ghost: a tinted status surface with no border, so they do not look pressable (rule/ghost-status-badges). primary is the single filled exception and should be used sparingly for prominent labels.

Counter chrome is variant-filled — counters use solid variant colours (filled) or tinted --la-color-surface-* fills (ghost). No border. This keeps counters visually louder than badges, appropriate for numerical signals.

Variant When to use
danger Urgent issues requiring immediate action
warning Proactive issues — not urgent but should be addressed
success Resolved items, positive states
neutral Locked, inactive, or unknown state
info Processing and awaiting states (In progress beside a step is warning, per status-conventions.md)
accent Category labels (e.g. "Doc Quality", "Legal Compliance") — badge type only, not a status
primary Prominent count or label against brand-primary context — default counter colour
Type When to use
badge Status or category label. Text-only or with a leading Phosphor fill icon (ph-fill ph-*).
counter Numerical count signal next to a title, nav item, or inbox. Single or multi-digit.

With tooltip: when a status concept may be unfamiliar to users (e.g. "DD window", "Processing"), wrap the badge in la-tooltip with appearance="light" to give context in one sentence. Dark tooltips feel too heavy against small badges.

Dot appearance (2 October 2026). Problem: a status column, where every row of a table says where a run is and, more quietly, how far it has got or who it is waiting on. Orion's Your playbooks table in new-design draws it by hand (05-playbooks.html, .pb-status): a 6px dot, the word, a faint detail, and for Blocked a la-tooltip around a span with tabindex="0" and a hand-drawn focus ring. A ghost pill on every row is chrome, so the dot says the state once (rule/state-said-once) and the word always says it in words.

appearance="dot" (badge type only) drops the pill: a 6px dot in the variant's state colour, the label in --la-color-text-secondary, and detail (string) after a middle dot in --la-color-text-muted, such as "2 of 10 steps" or "Waiting on HMRC". The dot is --la-color-urgent for danger, --la-color-proactive for warning, --la-color-resolved for success, --la-color-processing for info and --la-color-text-faint for neutral; accent (a category) and primary (for interactive elements) are not states and draw the neutral dot (rule/colour-keyed-to-state, rule/primary-colour-interactive-only). There is no icon, because the dot is the glyph, and detail is read by the dot only. The separator is its own node in --la-color-text-faint (ux-patterns 12) and is hidden from assistive tech, which reads "Blocked Waiting on HMRC".

  • Which variant: the paired-badge table in status-conventions.md: Complete success, In progress warning, Not started neutral, Overdue danger. Blocked is not in that table; it is danger (decided 2 October 2026).
  • Truncation: the host takes at most its cell's width. The detail gives way first, with an ellipsis; the word never truncates.
  • With a tip: the tip stays la-tooltip's job. Wrap the badge in la-tooltip appearance="light" max-width="280px" and put tabindex="0" on the badge itself, with no wrapper span: la-tooltip opens on :focus-within, and la-badge draws the system focus ring on :host(:focus-visible), for any appearance. A badge without a tabindex is not focusable, so nothing changes for it. In a narrow cell give the la-tooltip host max-width: 100% (placing it, which rule/no-page-classes-on-hosts allows) so the badge inside can shrink. la-tooltip does not wire aria-describedby yet, so a screen reader hears the status but not the tip: the tip carries help, never the only copy of something needed, in one sentence (rule/tooltip-one-breath).
  • When: dot for a status column in a table or list; ghost for a status that stands alone, in a header or on a card (rule/ghost-status-badges). One concept takes one appearance on a surface (rule/consistent-status-treatment).

Colour, decided by Jonard on 2 October 2026: In progress is warning (amber) and Blocked is danger (red). The dot is a paired text badge, a word naming the state, not a step marker, so it follows the paired-badge table in status-conventions.md rather than decision 104's colourless marker registers. Blocked is a wait on someone outside the company that the founder should notice, so it is danger rather than decision 104's gated (neutral).

Against the Orion drawing, for review: the detail is --la-color-text-muted rather than --la-color-text-faint, which is under AA contrast for text that is read; a middle dot now sits between the word and the detail, as the queue item and ux-patterns 12 have it; and Orion's Blocked tip runs to two sentences.

Consumers: in new-design: the Status cell of Orion's Your playbooks table (05-playbooks.html, .pb-status, built in viewLanding()), and in 03-deadlines.html the status line of the calendar's hover tip (.evt-tip-status: Overdue, Due soon, On track, an 8px dot beside a coloured, semibold word) and its legend (.cal-legend). Neither has moved onto it; they receive it through the sync. On 03 the move makes the tip's status quieter, with the word in ink rather than in the state's colour. Docs: docs-src/components/la-badge.html.

la-breadcrumb

A depth signal rendered in the page header. Shows the user's location in the navigation hierarchy and provides a one-click path back up the tree. Used inside la-app-shell via the breadcrumbs prop — not rendered standalone.

Props: items (BreadcrumbItem[]) — ordered array from root to current page. Each item is { label: string; href?: string }. Last item is the current page (no link).

Collapse behaviour: At 4 or more items, the trail collapses to root / ••• / parent / current. Tapping ••• (an la-icon-button) expands the full trail. Collapsing resets automatically when items changes.

Colour: Ancestor links use --la-color-text-muted; the current page label uses --la-color-text. Both pass WCAG AA on the page header's --la-color-bg-subtle ground. Hover on ancestor links resolves to --la-color-text. The separator uses --la-color-text-faint and is aria-hidden.

The earlier below-AA divergence (ancestors on --la-color-text-faint, current on -muted) was closed on 4 Sep 2026, when the trail became standard page chrome across the UK prototype — prototype-standards.md does not allow a published prototype to carry a divergence, so the component absorbed the fix.

Docs-only — see docs-src/components/la-breadcrumb.html.

la-button

The primary interactive control. Every call-to-action uses this. Always use a verb-first label in the Title Case structural register.

Variants: primary, secondary, success, danger, ghost Sizes: sm (28px), default (36px), lg (44px)

Variant When to use
primary The main action on a screen or panel. One per view.
secondary Cancel, back, or secondary actions alongside a primary
success Approve, complete, or confirm positive outcomes
danger Destructive actions — delete, remove, reject
ghost Low-prominence links or tertiary actions
Size When to use
sm Dense layouts — table row actions, widget headers, toolbar buttons
default The standard for almost every button across the product
lg Hero CTAs and large forms — unlock flows, onboarding, primary empty-state actions

Labels are consumer responsibility — la-button does not truncate. Keep labels short and verb-first. If a label needs to be long, the call-to-action isn't clear enough.

Loading state: the loading boolean prop turns any button into an async-CTA-ready button. Pattern B is the system default (label stays, spinner shown alongside) — opt into Pattern A with loading-label="Saving…" for high-stakes actions, or Pattern C with hide-label for minimalist contexts. Full guidance in design-language/loading.md §4.

Loading prop Type Default Notes
loading boolean false Suppresses click, sets aria-busy="true". Orthogonal to disabled.
loading-label string '' Pattern A — replaces default content during loading (e.g. "Saving…").
hide-label boolean false Pattern C — hides default content during loading; only spinner visible. Wins over loading-label if both are set.

Auto-route by icon-left: the spinner placement adapts to the button's content. Buttons with an icon-left slot show the spinner in place of the icon during loading (label stays). Buttons without an icon-left show the spinner centred in the label area (label fades). In both cases the button keeps its resting width — no phantom space, no jump on toggle. Pattern C with hide-label collapses the leading area entirely and centres the spinner regardless of icon presence.

Pairing with la-spinner: la-button embeds la-spinner internally. Spinner size and appearance are auto-mapped — sm-button → sm-spinner; default + lg → md-spinner; primary/success/danger variants → appearance="invert"; secondary/ghost → appearance="default". Consumers never set spinner props directly.

la-icon-button

An icon-only button for secondary actions in dense surfaces — widget headers, toolbars, sidebar toggles. Shares the --la-button-height-* size scale with la-button so mixed rows align at any size. Requires a label prop for screen readers (no visible text).

Variants: default, primary, outline, danger Sizes: sm (28px), default (36px), lg (44px)

Variant When to use
default Most common — transparent with hover fill. Widget headers, toolbars, inline controls
primary High-emphasis single action, used sparingly
outline Secondary emphasis — between default and primary
danger Destructive actions — delete, remove
Size When to use
sm Widget headers, dense toolbars, actions inline with text rows
default Standalone icon buttons in standard-density layouts
lg Touch targets or hero icon actions — rare

Use la-button with its icon-left or icon-right slot when you need an icon and a text label. la-icon-button is specifically for icon-only triggers.

la-input

A text input for forms and modal dialogs. Wraps a native <input> element with a consistent label, hint, icon slot, and state system. Width comes from the container; height has two sizes since 17 Sep 2026: default, and size="sm" (28px, --la-button-height-sm) so a search box sits level with la-button size="sm" and la-select size="sm" in a filter bar (rule/filter-bar-one-row). Source only until the bundle is rebuilt.

Types: text, email, password, search, tel, url, number

Prop When to use
label Always set for named form fields. Omit only for search inputs where the icon and placeholder provide sufficient context.
hint Use for format guidance ("DD/MM/YYYY") or constraints ("As registered with ASIC"). Turns red in error state.
required Appends * to the label and forwards required to the inner input. Use on mandatory fields.
error Set programmatically after validation. Pair with a hint that explains what's wrong.
disabled Pre-filled read-only fields — e.g. jurisdiction locked to a value.

Icon slots: icon-left for context (envelope, person, lock), icon-right for actions (password reveal) or status (validation check). Padding adjusts automatically — no extra props needed.

Search inputs are a separate component (la-search-input, not yet built). Use type="search" on la-input as a temporary measure only — the native clear button is not styled.

Height (6 Oct 2026): the default input is 36px, --la-button-height-md, so a button beside it matches; it was padding-driven at 38px, off the button scale. size="sm" stays at 28px. la-select and la-date-input moved with it.

la-date-input

A segmented text-entry component for a known single date. It removes browser-specific native date chrome while retaining fast keyboard entry, explicit format guidance, whole-date validation, and an ISO YYYY-MM-DD value for storage.

Problem solved: Founders need to enter exact dates they already know (for example, an expected investment closing date) without guessing the locale format or navigating a calendar. Native type="date" controls are inconsistent across browsers, while a free-text field makes invalid and ambiguous dates too easy.

Prop When to use
value Controlled ISO date (YYYY-MM-DD). Empty while entry is partial or invalid.
locale Determines the visible segment order and formatted constraint messages. Defaults to en-US.
label / aria-label Name the date. Use aria-label when the surrounding question already provides the visible label.
hint Optional supporting guidance. The component always falls back to the locale format.
min / max ISO boundaries for the valid date.
required / optional / disabled / error Mirror la-input.

Event: la-change — { value: string, valid: boolean, complete: boolean }. The value is ISO only when the full date and constraints are valid.

Keyboard: Numeric entry auto-advances only after a segment is complete. / or - advances explicitly; Backspace from an empty segment returns to the previous one; Left/Right move between segment boundaries. Pasting a complete numeric date follows the visible locale order.

Composition boundary: This component never opens a calendar. A future la-date-picker should use la-date-input as its typed-entry surface and own calendar disclosure, focus management, and surrounding-date selection. A future la-date-range should compose two labelled date inputs (and optionally a shared picker), then own start/end ordering and range-specific validation. Do not add picker or range state to la-date-input.

la-menu + la-menu-item + la-menu-toggle + la-menu-divider

Tertiary action surface — a 3-dot trigger button that reveals a floating list of actions. la-menu owns the trigger, panel, and open/close lifecycle. la-menu-item is the action row primitive: label, optional icon, and a danger variant. la-menu-toggle is a switch row for boolean in-menu settings (does not close the panel on change). la-menu-divider is a visual separator between sections. Status: 🟢 v1 ready (2026-05-07) — full reference at docs-src/components/la-menu.html.

Problem solved: Every page or card surface needs a consistent home for tertiary actions (rename, delete, export, etc.). Before this, teams were inventing ad-hoc popouts with inconsistent styling, shadow, and keyboard behaviour. la-menu is the one canonical answer — reach for it whenever an action doesn't warrant a visible button and isn't the primary CTA.

trigger slot (17 Sep 2026): slot any button as slot="trigger" to open the panel from a labelled la-button, an icon button with another glyph, or a select-like control; the menu sets expanded / aria-expanded and aria-haspopup on it and returns focus to it on Escape. Without the slot the 3-dot la-icon-button remains. la-menu-item gained radio + checked (role menuitemradio, trailing check) for one-of groups such as Sort by. Source only until the bundle is rebuilt.

origin property: Controls which corner the panel scales from. Set to match the trigger's position on the page — top-right (default) for a 3-dot button in the top-right of a card, bottom-right if the trigger is near the viewport bottom.

Events: la-menu-open / la-menu-close (from la-menu), la-menu-select with {label, value} (from la-menu-item, bubbles), la-menu-toggle-change with {label, value, checked} (from la-menu-toggle, bubbles — does not trigger panel close).

la-select

Custom single-select combobox. Trigger chrome mirrors la-input (height, border, focus ring, error, label, hint — and size="sm" since 17 Sep 2026) so a select sits naturally in a form row alongside inputs or in a one-row filter bar. la-option takes a count slot (<span slot="count">4</span>) for a quiet tabular count beside the label; the slot is not part of the label the trigger copies (getLabel() reads the default slot only). Source only until the bundle is rebuilt. Slotted <la-option> children carry the values; rich content (icons, multi-line) is allowed inside each option. Status: 🟢 v1 ready (2026-05-05) — full reference at docs-src/components/la-select.html.

Why custom (not native <select>): native renders the open dropdown via the OS, which means we can't style options, hover, selected state, or icons inside the panel — every product surface would render differently across macOS / Windows / Linux. Custom is more code but gives us full token control and a consistent feel.

Prop When to use
label Always set for form fields.
placeholder Shown in the trigger when no value is selected. Defaults to 'Select…'.
hint Format / constraint guidance, same convention as la-input.
required / error / disabled Mirror la-input.
value Controlled — consumer updates from la-change.
name Form field name. Reserved for future ElementInternals form-association (out of scope in v1).

Partner — la-option: slotted child carrying value (required), disabled, selected (reflected by parent — do not set directly). Default slot accepts plain text or rich content (icons, multi-line); plain-text fallback used for type-ahead matching via textContent. No own events — selection always travels through the parent's la-change.

Selection glyph: the inline check on the chosen option is ph-check (plain). Distinct from ph-check-circle which is reserved for the success status — see iconography.md § Form selection and decision 59.

Keyboard: ↑/↓/Home/End cycle, Enter/Space select, Esc closes, Tab closes-and-progresses, type a printable character to jump to the next option starting with that letter. Type-ahead matches single characters only — no buffer in v1.

Positioning: panel floats below by default. When there's not enough space below (e.g. select sits near the viewport bottom), it flips above. Panel uses position: absolute inside the host's shadow DOM — an ancestor with overflow: hidden will clip it. v2 candidate: switch to the Popover API for top-layer rendering when an overflow-clip case appears.

Out of scope (deferred to v2 with a solve): multi-select, search input inside the panel, ElementInternals form-association.

la-select vs filter-menu — when to reach for which

Use la-select when Use a filter-menu (overlay of la-checkbox) when
Picking exactly one value Picking multiple values
The select sits in a form row alongside inputs The trigger sits in a toolbar next to other action buttons
Default state shows the chosen value as text in the trigger Default state shows a count ("3 selected") or a pill list
The selected value is the row's data ("Jurisdiction: Australia") The selected values filter or filter-out other content

If the answer is "single + form-row," reach for la-select. For multiple values in a form row (capturing a set as data — jurisdictions, tags, OpCos), reach for la-multi-select (decision 103). For "multiple + toolbar/filter" (selections that filter other content), compose la-checkbox rows inside an overlay — pattern is documented in la-data-table's filter-menu snapshot.

la-multi-select

Problem: forms need to collect several values from a known set while showing current selections and surfacing the rest at a glance, without a heavy overlay dropdown — uncovered by la-select (single, overlay) or la-choice (one-per-group). Token field: selections are removable chips behind a search glyph; remaining options render below as one-tap "+" suggestion pills; typing filters them inline (no overlay). options/selected accept comma-separated strings (HTML) or arrays (JS); max-suggestions caps pills; allow-custom permits typed values; standard label/hint/required/error/disabled chrome matched to la-input. Fires la-change {selected, action, value}. Docs at docs-src/components/la-multi-select.html; decision 103. This is the "multiple + form-row" primitive the table above previously said didn't exist.

la-stepper

A stepped progress indicator for multi-step flows. Shows where the user is in a sequence and what's been completed or skipped. Used in the unlock flow.

Step statuses: pending, active, complete, processing (deferred), skipped

A horizontal bar of equal-width pills, one per step, with no labels drawn. complete and active are primary (the last primary pill is where you are), pending a light rail, skipped a muted gap. Green is only for a circular marker with a check, la-step-marker, never these pills (Jonard, 9 Oct 2026: briefly green that day, then back). Use when a process has a defined sequence with discrete steps the user must move through in order.

Status markers (done / in progress / to-do / gated / attention / processing) follow the cross-cutting standard in status-conventions.md — la-stepper is the linear sequence register. Match it for any new stepper, phase plan, or checklist.

la-step-ring

Problem: secondary multi-step flows (phase plans, sub-step checklists, card-level progress) need a compact at-a-glance progress read, and the segmented donut was being hand-rolled in prototype JS in two places (the RIF overview focal ring + the project-card phase rings) — duplicated geometry, drifting styling. One component owns it.

The radial cousin of la-stepper (linear) and la-spinner (indeterminate): a donut split into one rounded-corner segment per step — green for completed steps, half-toned primary for the current step, muted for what's still ahead.

Props: total (number, default 1), done (number, default 0), current (boolean, default true — renders the step after done as in-progress), thickness (viewBox units, default 6), gap (degrees between segments, default 4), corner (corner radius in viewBox units, default 1.4 — subtle, not a full pill), label (centre text, e.g. "3 of 6" or a phase number), sublabel (line under the label, e.g. "Done").

Follows the sequence register of the status standard (status-conventions.md) via segment fills: done = green (--la-color-resolved, since 9 Oct 2026, decision 104 amended), current = primary at 0.5, pending = muted.

Geometry lives in a fixed 52×52 viewBox so the shape is identical at any rendered size — size via --la-step-ring-size (default 120px) or the host's width/height. Centre content uses label/sublabel, or slot arbitrary markup (the default slot wins when filled). Tuning CSS vars: --la-step-ring-size, --la-step-ring-done / -now / -future (colours), --la-step-ring-now-opacity, --la-step-ring-label-size, --la-step-ring-sublabel-size. Display-only — no events. Crisp filled sectors (no blur filter); respects prefers-reduced-motion trivially as it has no motion.

la-step-marker

Problem: the marker on a step was re-declared by every page that drew steps, three different ways in Phase B alone (the playbook run at 28px, the e-sign ceremony with a green done, the wizard rail), though decision 104 fixed one mapping. One component now holds it, so a page can't drift from the standard.

The marker on a step, in either register of the status standard:

  • variant="sequence" (default) for ordered steps: a 22px numbered circle. active is primary with its number; complete is green (--la-color-resolved) with a check, so a done step can't be read as the one in hand (decision 104, amended 9 Oct 2026). pending is muted. Beyond that, colour only for the exceptions: attention (danger surface, warning glyph) and processing (spinner, after launch).
  • variant="check" for unordered sub-tasks inside one step: a ~20px check-circle icon. Green (--la-color-resolved) for complete only; active a solid primary dot; the rest grey.

Props: status (pending default · active · complete · gated · attention · processing · passed), variant (sequence · check), index (number shown while pending or active; sequence only), label (accessible name, defaults to "Step N: " in the paired-badge words; label="" makes the marker decorative when its row already says the state). No events. Part: mark. Tokens: --la-step-marker-size (22px), --la-step-marker-check-size (20px), --la-step-marker-glyph-size (12px), --la-step-marker-passed-glyph-size (11px), --la-step-marker-ring (1.5px).

Words (9 Oct 2026): GOV.UK's task statuses, in the accessible name and the paired badge: Completed, In progress, Not yet started, Cannot start yet, There is a problem. Processing and Moved past are ours; GOV.UK has neither.

Passed (decision 115, 6 Oct 2026): a step the person moved past with a reason, so they're never blocked. It has no fill, a 1.5px dashed --la-color-text-faint ring and ph-bold ph-arrow-bend-down-right in --la-color-text-muted, in both registers. It's quieter than pending, so it reads neither as done nor as still to do. Its accessible name and paired badge read "Moved past". A step that doesn't apply isn't a status: it leaves the list.

Not pressable (9 Oct 2026). It shipped with an interactive mode, a toggle that ticked the step; nothing used it, and Carbon's progress indicator, Material's non-linear stepper and GOV.UK's task list all navigate to a step rather than tick it from the marker. It was removed. A step is finished from its own button.

Basis (reviewed 9 Oct 2026, the docs draft's Basis table): the numbered circle and check, active in primary, muted pending and the error state follow Material's steppers and Carbon's progress indicator. Green for done follows the success colour in Atlassian's lozenge, Polaris's badge and Carbon's status indicators, against GOV.UK (which leaves Completed uncoloured) and the Material and Carbon steppers (primary). The lock, the passed look and the cross-fade are ours.

Motion: the number and the check cross-fade (fade, scale, a touch of blur), as motion.css's t-icon-swap does on the page. Off under prefers-reduced-motion.

Not this: a progress overview of a whole sequence is la-step-ring (radial) or la-stepper (linear). la-journey-steps still draws its own indicator (20px) and should move onto this.

Consumers: the Orion playbook run (16-playbook-run.html, every step's number) and the e-sign ceremony (17-esign.html, its three steps) in new-design, since 2 Oct 2026. Docs: docs-src/components/la-step-marker.html (v1 ready, 9 Oct 2026).

la-progress

Problem: Orion's Phase B screens draw a determinate bar by hand in two places, at two heights, in two colours and with two motions, for one idea: how far a playbook run has got. The playbook modal's In progress rows draw a 96 by 4px ink bar that scales; the run's plan overview draws a 6px green bar that animates its width. la-sidebar's setup checklist draws a third, green again. The loading family named this primitive in April (decision 45, loading.md §2.8) and it was never built. One component now holds it.

A determinate progress bar: one continuous fill for how far a known quantity has got, such as the steps of a run, the items of a batch or the bytes of an upload. Monochrome: a --la-color-text-secondary fill on a --la-color-bg-muted track, both with pill ends.

Props: value (number, default 0; clamped to 0 to max, and 0 when not a number), max (number, default 100, so value alone is a percentage; pass the step count when the value is steps; anything not above 0 falls back to 100), label (accessible name, default "Progress"; label="" makes the bar decorative), value-text (the value in words for assistive tech, such as "2 of 10 steps"; unset, it reads "40%" on the default scale, or "2 of 10" once max is set), size (default · lg). Slots: none · Events: none · Parts: none.

Size Height Where Orion draws it today
default 4px Beside a label in a row: the playbook modal's In progress rows (and la-sidebar's checklist)
lg 6px Heading its own panel: the playbook run's plan overview

Width is the container's: the host is block-level and full width. In a flex row, give the host a width, as the modal row does (width: 96px; flex: none). A page may size and place the host, never paint it (rule/no-page-classes-on-hosts).

Colour. Never green, never primary, and no tone. The fill is the same ink at 100% as at 40%: progress through a sequence is monochrome (status-conventions.md, decision 104), green is kept for a checklist's completion check, and --la-color-primary is for interactive elements (rule/primary-colour-interactive-only). A run that is complete, blocked or overdue says so in the badge or text beside the bar, once (rule/state-said-once): the modal's blocked run keeps its bar, and its meta reads "Blocked · Awaiting HMRC". A tone prop waits for a use that needs one.

la-segmented

Problem: a Review, Decide & Confirm step asks some questions once per person ("Which exemption does each angel fit?"), one row per investor with a short answer on each. Pick one of two to five short options, in a row: a radio group drawn as one track. An input, not navigation (Jonard, 8 October 2026): it can sit in a form beside la-input and la-select, at their heights, and the page reads its value as it reads theirs. la-tabs, even variant="segmented", is navigation: each tab shows a different panel or view. la-segmented holds la-segment children, in the same way la-select holds la-option; each segment's text is its label. Modelled on Astryx's SegmentedControl (Meta, v0.6.6), whose limits and variations it takes (Jonard, 8 October 2026): two to five options, three sizes, hug or fill, icons beside a label or alone, a disabled option, and a message saying why the whole control is disabled.

  • Neutral. The track is --la-color-bg-muted and the picked segment is raised in --la-color-bg with --la-shadow-xs, in the text colour. It never uses primary or a status colour, because on a playbook step the pick is the founder's answer, not our verdict (Phase B brief, Screen 1). Nothing is picked until someone picks.
  • Wraps, never truncates. The track is flex-wrap, so long labels go onto a second row in a narrow column rather than overflowing. With layout="fill" the segments share the width equally, and one that can't fit its longest word moves to a second row. Its radius is --la-radius-md and each segment's is --la-radius-sm, which reads right on one row or two.
  • Where it differs from Astryx, on purpose. Astryx always has one option picked; here nothing is picked until someone picks, because on a playbook step the pick is the founder's answer and is never made for them (decision 117). A view switch sets value. Astryx truncates a long label; here it wraps, because the founder has to read the whole answer.

Props (la-segmented): value (the picked segment's value, reflected; "" when none is picked) · label (the group's accessible name: say what's being answered, such as the person's name) · size (sm 28px · default 36px · lg 44px, beside a large button: la-input's and la-select's heights, so it lines up in a form row; each segment is the height less the track's 2px padding) · layout (hug, the default: segments fit their labels · fill: equal shares of the width) · disabled · disabled-message (why it's disabled, in la-tooltip on hover and focus; the control stays focusable and is described by the message, and nothing can be picked. Don't wrap a disabled control in la-tooltip instead: it swallows the hover). Props (la-segment): value · disabled · hide-label (icon only: the label is read, not shown, and the segment is square; only for icons that say what they are, such as grid and list) · checked (set by the parent, reflected for styling; don't set it yourself). Slots (la-segment): the label · icon, before the label (--la-font-size-lg sm, -xl, -2xl lg). Event: la-change {value}, bubbles and composed, when someone picks a different segment. It doesn't fire when value is set from script. Parts: track on the group, segment and label on each segment.

Keyboard and ARIA: the host is role="radiogroup" named by label, and each segment is role="radio" with aria-checked. There's one tab stop: the picked segment, or the first enabled one. Arrow keys move and pick (Left and Up go back, Right and Down go on, wrapping round), Home and End go to the ends, and Space or Enter picks the focused segment. Disabled segments are skipped and carry aria-disabled. Under forced colours the picked segment gets an outline.

Targets and motion: the control is 36px (28px sm, 44px lg), and each segment pads to 44px on a touch screen. Every size is a token: the button heights, --la-space-3xs for the track, the font sizes for icons. Background, colour and shadow change on --dur-fast --ease, and are instant under prefers-reduced-motion.

When to use: two to five short options, picked inline, where every option should stay in sight: the answer per person on a step, or a switch between views or modes on a workbench or toolbar. Not this: options that need a description or a Recommended mark are la-choice in a radiogroup. Six or more options, or long labels, are la-select. Moving between pages or panels is la-tabs, and a single on or off is la-switch.

Contrast (WCAG 2.2 AA, as Astryx sets it): labels 4.5:1 in every state (secondary on the track 6.93:1, text on the picked segment 15.36:1); an icon with no label 3:1; the focus ring 3:1. Deferred (Jonard, 8 October 2026): the picked segment is told apart by its raised white (1.09:1 on the track) and a darker label (2.03:1 against the unpicked one), below the 3:1 Astryx asks for where people rely on the selected look. la-switch vs la-checkbox — when to use which

Use la-switch when Use la-checkbox when
The change applies instantly — settings, feature flags, preferences The value is staged — part of a form submitted later
The control is binary and permanent in UI A multi-select or list selection
You want SR users to hear "on"/"off" You want SR users to hear "checked"/"unchecked"
A clear "off" state is a meaningful UI affordance An indeterminate state is possible

la-checkbox vs la-choice — when to use which

The rule: la-choice is a statement. la-checkbox is a control.

Context Reach for Why
Onboarding / unlock steps with descriptions la-choice The row is the moment of attention — built-in label + description, cushioned padding, contained variant
Consent & agreement lines ("I agree to the terms") la-choice Full-row attention matches the weight of the decision
Settings-style forms (one label per row, maybe a description) la-choice Each row tells a story
Table row selection la-checkbox The table owns the row — checkbox is one control among many cells
Filter menus, sort dropdowns, "show columns" popovers la-checkbox Menu rows are dense (28–32px) inside an overlay — la-choice's cushioned padding would feel bloated
Bulk-action toolbars la-checkbox Inline control next to actions; no description needed
Form grid cells ("Admin?" column in a team table) la-checkbox Grid structure owns the labelling

la-data-table

A data-driven table primitive. Consumer passes columns and rows as properties; the component owns sort, selection, row-click dispatch, sticky header, density, and the empty / loading states. Everything is controlled — sort and selected arrays flow in via properties and flow out via events, so the consumer owns the state.

Props:

  • columns (DataTableColumn<T>[]) — column definitions. Each column: id, label, optional align, width, sortable, render(row).
  • rows (T[]) — the dataset.
  • rowKey (keyof T | (row: T) => string, default 'id') — stable row identifier used by selection and sort.
  • sort ({columnId, direction: 'asc' | 'desc'} | null) — current sort. Controlled — consumer updates from la-sort-change.
  • selected (string[]) — currently-selected row keys. Controlled — consumer updates from la-selection-change.
  • selectable — 'none' (default) / 'single' / 'multi'. multi adds a checkbox column + header select-all.
  • density — 'compact' / 'default' / 'comfortable'. Controls vertical and horizontal row padding via --la-dt-row-pad-v / --la-dt-row-pad-h.
  • sticky-header (boolean, default true) — pins the header when the wrap scrolls.
  • loading (boolean) — replaces the body with skeleton rows (or the loading slot).
  • row-clickable (boolean) — pointer cursor on every row without enabling selection; use when rows are navigable.

Slots: empty (overrides default "No results"), loading (overrides default skeleton rows).

Events:

  • la-sort-change — {columnId, direction} | null. Fires when a sortable column header is activated. Cycles asc → desc → off.
  • la-row-click — {row, rowKey}. Fires on any row click; in selectable='single' this also toggles selection.
  • la-selection-change — {selected: string[]}. Fires on checkbox toggle, header select-all, or single-row click.

States: default row, hover row, selected row, sortable header (idle / hover / sorted asc / sorted desc), focus-visible on sortable header (Enter/Space activates), loading (skeleton shimmer, opacity-only), empty ("No results" or consumer slot).

Composition: uses la-checkbox inside shadow DOM for the header select-all and each row's checkbox in multi mode. Row-checkbox clicks stop propagation so they don't trigger la-row-click.

Accessibility: native <table> / <thead> / <tbody>. Sortable <th> gets role="button", tabindex="0", and aria-sort="ascending | descending | none". Keyboard Enter/Space activates sort. Non-sortable headers stay role="columnheader". Sort-direction icon is aria-hidden="true". Composed checkboxes get label props ("Select all rows", "Select row {key}").

Motion: row hover + sortable header colour transitions use --dur-fast × --ease. Skeleton shimmer is an opacity keyframe (GPU-safe). @media (prefers-reduced-motion: reduce) kills transitions and the shimmer.

Gate 8 noted exceptions: width: 40px on the checkbox cell + <col> and height: 12px on skeleton rows are hardcoded — no current token for checkbox-column width or skeleton-row height. Matches the la-checkbox / la-upload-box precedent for glyph-detail pixel values.

Known v1 limits: no virtualisation (every row renders), no column resize / reorder, no inline filter UI (sort only), no row expansion / subrows, no selection-preserving re-sort beyond what the consumer maintains via selected + rowKey. These are explicit deferrals — the primitive is for "dataset rendering," not "full spreadsheet."

la-tabs[vertical] vs la-sidebar — when to use which

Both are vertical lists with single selection. They serve different scopes:

Component Scope Variant focus
la-tabs[variant='vertical'] In-page tab pattern. Panels swap in place; no URL routing. Lives inside a card, modal, settings dialog. Carries role="tablist" semantics. Sizes, density (in-page concerns)
la-sidebar App-shell navigation. Items route to different views/URLs. Lives at the edge of the app. Collapsed icon-only, brand area, footer slot, multi-section grouping (app-shell concerns)

This split matches Material UI, Radix, Ant Design, and Chakra — every major design system supports vertical orientation on its tabs component while keeping the app sidebar separate. The variant sets are intentionally different — sidebar's collapsed-icon mode is meaningless inside a settings panel, tab sizes are meaningless on a full-height app rail. See decision 43.

Hierarchy rule — pick the variant that matches the navigational tier:

  1. segmented (most prominent): page-level / primary content nav
  2. underline: legacy chrome only — reach for it second
  3. pill: section-level inside a card or panel
  4. vertical: orthogonal layout choice, not a prominence step

Don't nest the same variant in itself; if a panel needs tabs, drop down to pill. Don't pair siblings of different tiers in the same band. Don't reach for vertical to mean "smaller" — it's a layout call, not a size call.

v1 a11y baseline — full ARIA tablist semantics (role, aria-selected, aria-controls, aria-labelledby, aria-orientation), roving tabindex, focus rings on all variants, multi-channel active state (colour + indicator). Reduced-motion auto-respected via --dur-base token cascade.

Known v1 limits — no explicit mobile / narrow-width handling: long labels overflow horizontal rails (intentional, documented in "Long labels" snapshot, locked to variant="underline" because the overflow shape is rail-specific). No auto-scroll, no collapse-to-more-menu in v1. Disabled state on individual tabs not yet wired.

Problem: Orion's playbooks page draws its area cards by hand: .area-card from areaCard() in 05-playbooks.html, under the library's All areas, and under the landing's Where to start when we have read nothing yet (?state=unread). Each card is a <button> with its own copy of the area mark, its own shadow lift, and an arrow that appears on hover only; keyboard focus gets the lift and no ring. One legal area as a card that opens it: the area's mark (la-area-icon, md, 40px), its name, a quiet count line, a line under that (the area's sub-groups, or its description), and an arrow that slides in on hover and focus.

Props: area (governance · employment · data · fundraising · commercial · ip, reflected and passed to la-area-icon, which owns the colour and the glyph; anything else takes the neutral pair), label (the area's name, and the card's accessible name), sublabel (the count line, such as "4 journeys · 26 documents"), description (the sub-groups joined with " · " where the area has them, otherwise the area's description; the page decides which, as areaCard() does), href (set, the card is an <a>; unset, a <button type="button"> and the host routes on the event). Slots: none. Event: la-area-click {area, href}, bubbling and composed, on activation in both modes; the name is la-legal-area-widget's. Parts: none. label and sublabel are la-tile's names for the same two lines.

Why not a la-tile variant. The content is alike (a mark, a name, a count). The contract is not:

A variant would need a surface switch, a role switch (a pressed toggle against a link), a third line, wrapping, a second mark and a way out of the hairlines: a second component behind one tag. la-tile and la-tile-strip are unchanged, so LawVault's shelf (Orion and Pharos) and the playbooks page's documents shelf render and behave as before.

Surface and motion. Elevated, --la-radius-lg, --la-space-lg padding. It lifts on hover and on keyboard focus: two layers carry --la-shadow-md and --la-shadow-card, and their opacity cross-fades over --dur-base --ease, so only opacity animates (rule/motion-gpu-safe). la-insight-card and la-module-tile transition box-shadow itself, which is a review call for them. The arrow (ph-bold ph-caret-right, 14px, --la-color-text-faint) fades in and slides 4px over --dur-fast --ease. Under prefers-reduced-motion both change at once. In forced-colours mode the card takes a 1px CanvasText border, because forced colours drop shadows and the card would lose its edge.

Type. The name is --la-font-size-md semibold; the count line --la-font-size-sm in --la-color-text-muted, --la-space-3xs under it; the description --la-font-size-sm in --la-color-text-secondary, --la-space-sm under the counts. Line heights are the prototype's: 1.3 for the name and the counts, 1.45 for the description (the prototype's button drew the count line at normal, about 1.2; 1.3 lands within a pixel). The name and the arrow share the first line, so a long name wraps before the arrow; in the prototype the arrow was placed over the card and could sit on a long name's last few pixels. Text wraps under the tokens' text-wrap: pretty (decision 83), as in every component, so a description can break a word earlier than the prototype's light-DOM card did: Data Protection's last line reads "a breach." rather than a lone "breach.".

Accessibility. One link or button, one tab stop; the host takes no focus. aria-labelledby names it by the area's name alone, so voice control finds it by what it shows and a screen reader says "Employment, link" before anything else; aria-describedby adds the count line and the description. la-area-icon and the arrow are decorative. Focus shows the system ring (--la-focus-ring-width in --la-color-border-focus, offset --la-focus-ring-offset) as well as the lift and the arrow. Prefer href: a link opens in a new tab and shows its address, and a hash router picks it up without a click handler.

The grid is the page's. The host is block-level and fills its grid cell, so the cards in a row share a height. Orion lays them out in three columns, two under a 1000px window and one under 760px, with a --la-space-md gap; the docs draft gives that CSS with minmax(0, 1fr) columns, so a long word can't widen a column. Insight improvement aside — design pattern

The aside panel on the legal area page (and other insight-based views) follows a specific pattern: it is an intake coach, not a form.

What it does: Collects context, data, and documents from founders to improve the quality of their insights. Current content: actions to add context, and related documents to browse or upload. Future: step-by-step guided plans.

Mental model: The founder reads their insight (consumption mode), then opens the aside to improve it (intake mode). These modes don't coexist — founders context-switch cleanly.

Design principles:

  • Every item in the aside carries a why — "We're missing your cap table — adding it would improve this insight significantly." Not just a label and a button.
  • Progress and completion states are important — make the founder feel the progress they're making, not the gap that remains.
  • Empty state: inviting and explanatory, never blank.
  • Never feels like a form. The aside earns the interaction by showing the value of each contribution.

Entry point: The trigger to open the aside (on tablet: overlay; on desktop: always visible) should frame the value, not describe the action. "3 ways to strengthen this insight" is better than "Open actions panel."

Tablet behaviour: Overlay drawer (see design-language/layout.md — aside panel at tablet widths). Full-width content when reading, full-attention aside when acting.

Components that live in the aside:

  • la-actions-widget — actions the founder can take to improve the insight
  • la-document-list — related documents that are inputs to the insight

Naming convention

All components are prefixed la- (LawAdvisor). This:

  • Avoids collision with native HTML elements
  • Makes it obvious which elements are custom when reading HTML
  • Groups all library components together in tooling

Component API patterns (Lit)

Properties vs attributes

  • Use @property() for data passed from JS (arrays, objects, booleans)
  • Use @property({ type: String, reflect: true }) when the attribute should be readable in CSS or DevTools
  • Boolean attributes follow HTML spec: presence = true, absence = false

Slots

Use named slots for structural content, default slot for body content:

<la-panel>
  <span slot="title">Panel title</span>
  Content goes here
</la-panel>

Events

Dispatch CustomEvent with bubbles: true for coordination with parent components. Document all events in the component's rationale entry.

Membership is a selection, not a switch (approved 17 Sep 2026)

Including an item in a set — a document in a pack, a person in a list — is an add/remove action with a count, drawn with la-choice or an add/remove control, never an on/off la-switch. A switch reads as a setting; membership is a decision the founder can see the total of. The Due Diligence Pack is out of Phase A, so this is a pattern for its return.
