la-data-room-page

The Data Room document library. A read-only, cross-area view of the founder's collected documents, grouped by legal area — Governance and Employment only, per decision 75. Browsing only: uploads happen on the legal area pages, not here. Investor management lives in la-investors-page, a separate sub-tab (decisions 71, 82).

Anatomy

A single scrollable content column (840px max-width, centred). Page header with a ready-count subtitle, then one document section per legal area.

Anatomy — both areas populated

Content column .content 840px max-width, centred. The host scrolls (overflow-y: auto); the column carries the vertical rhythm (--la-space-2xl gaps).
Page header .page-header "Data Room" title plus the ready-count subtitle — "N documents ready to share". The count includes only Governance and Employment documents with status: 'ready'.

la-data-room-page

Page-level component. Owns the grouped-library layout only — no selection state, no modals, no uploads. The parent application passes the full document set; the component filters by category and derives the ready count. Designed to be placed directly inside an la-app-shell main slot.

Properties

PropertyAttributeTypeDefaultDescription
documents — DocumentData[] [] All vault documents. Each is grouped by its category ('Governance' | 'Employment'); documents with any other category are ignored.

Events

The page fires no events of its own. Row interactions come from the composed la-document-list / la-document-item children — la-select bubbles up through the page (bubbles: true, composed: true), so listen on the page element or above to route to the document detail view.

Interfaces

DocumentData

Imported from la-document-list — one shared row shape across every document surface.

interface DocumentData {
  name: string;
  association?: string;     // e.g. "Acme Corp." or a person's name
  status?: DocumentItemStatus; // 'ready' | 'processing' | 'failed' | 'none'
  error?: string;           // failed-row message
  category?: string;        // 'Governance' | 'Employment' — drives grouping here
  inDefaultPack?: boolean;  // DD-pack membership (unused on this page)
}

Usage examples

Basic wiring in a prototype

<la-data-room-page id="drp"></la-data-room-page>

<script>
  document.getElementById('drp').documents = [
    { name: 'Articles of Incorporation', status: 'ready', association: 'Acme Corp.', category: 'Governance' },
    { name: 'Board Resolution — Share Issuance', status: 'ready', association: 'Acme Corp.', category: 'Governance' },
    { name: 'Employment Agreement — Alex Chen', status: 'ready', association: 'Alex Chen', category: 'Employment' },
  ];
</script>

Lit template

html`<la-data-room-page
  .documents=${this.vaultDocuments}
  @la-select=${e => this._openDocument(e.detail)}
></la-data-room-page>`

Notes

  • Scope is decision 75 — Governance + Employment sections only. No Fundraising section, no default-pack tab, no missing-document tracking. Bringing any of those back is a product decision, not a page tweak.
  • Read-only by design — no upload affordance here. Documents are added on the legal area pages; the Data Room is the cross-area view of what's been collected.
  • Investors are a separate page — investor list, DD-pack sharing, and per-investor detail live in la-investors-page (decisions 71, 82). An earlier draft of this page combined both; the split is deliberate.
  • Height: :host is display: block; height: 100%; overflow-y: auto. The parent container must have a defined height. Place directly inside an la-app-shell main slot or a flex container with a fixed height.
  • Empty sections disappear: an area with zero documents renders nothing — no empty section header. With no documents at all, the page shows only the header with "0 documents ready to share" and no further guidance. Logged as a Minor heuristic finding (H2/H7 — empty state doesn't teach the surface); acceptable while the page is only reachable after documents exist, revisit if the route opens earlier.
  • Ready count is filtered: the subtitle counts only Governance and Employment documents with status: 'ready' — processing and failed rows appear in their sections but don't count.
