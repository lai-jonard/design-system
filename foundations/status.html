Foundations · Status conventions

Status conventions

The single source of truth for how we mark progress state on steps and tasks: the checks, numbers and markers used across every flow and subflow. Read this before building any stepper, phase plan, checklist, wizard or progress display, so that “done”, “in progress” and “to do” read the same everywhere. Decided in decision 104 (amended 9 Oct 2026) and decision 115. Every marker on this page is la-step-marker.

Two registers

Status looks different depending on whether the items are an ordered sequence or an unordered checklist. Pick the register by the nature of the steps, then use the marker below. The meaning of each state is the same in both registers; only the form differs.

Sequence registerChecklist register
Use for Ordered steps you move through in turn: phase plans, wizards, la-stepper, la-step-ring Unordered sub-tasks inside one step: they needn’t be done in order
Marker Numbered circle (22px) Check-circle icon (20px)
Colour Active is primary, complete is green, pending is grey Green for complete, a primary dot for active, otherwise grey

Why hybrid: a sequence carries its meaning through position and number; a checklist has no position, so a green check is the clearest sign of done. In both registers green means done and nothing else. Beyond done, colour appears only for the exceptions (attention, processing).

Amended 9 Oct 2026. The sequence register was monochrome: done and active were both primary, told apart only by check and number. Done is now green, so it can’t be read as the step in hand. Success is green in Atlassian’s lozenge, Polaris’s badge and Carbon’s status indicators; GOV.UK’s task list leaves “Completed” uncoloured, and Material’s and Carbon’s steppers use the primary colour.

The states

Seven states. A step that doesn’t apply isn’t one of them: it leaves the list, and its reason goes at the foot.

  • complete: finished.
  • active: in progress, where you are now.
  • pending: not yet started, but available.
  • gated: can’t start until an earlier step is done.
  • attention: overdue, failed, or needs action.
  • processing: work underway in the background. After launch: it was Auto mode’s, which isn’t in Phase B.
  • passed: moved past with a reason, so the person is never blocked (decision 115, 6 Oct 2026).

Radial — la-step-ring

The ring is a sequence progress overview, so it follows the sequence register through its segment fills: complete → green (--la-color-resolved, since 9 Oct 2026), active → primary at 0.5 opacity, pending → muted. Per-segment gated / attention are not shown in the ring: it shows progress, not per-step exceptions, so surface those in the list beside it. la-stepper, the linear bar, stays primary: green is only for a circular marker with a check.

Paired text badge

When a row also carries an la-badge (e.g. the phase plan), the variant matches the state so the marker and the badge never contradict. The words are GOV.UK’s task statuses where it has one; la-step-marker names itself with the same words (“Step 3: Completed”). Processing and Moved past are ours.

The component

The markers were page-scoped CSS until a second consumer appeared outside the RIF overview. Since 2 Oct 2026 they are one component, la-step-marker (variant="sequence | check", status, index), so the mapping is held in one place. New surfaces use it rather than re-declaring the tables above.
