Foundations · Status conventions

Status conventions

The single source of truth for how we mark progress state on steps and tasks — the checkmarks, numbers, and markers used across every flow and subflow. Read this before building any stepper, phase plan, checklist, wizard, or progress display so that "done", "in progress", and "to-do" read the same everywhere. Decided in decision 87; the living reference is the RIF project overview.

Two registers

Status looks different depending on whether the items are an ordered sequence or an unordered checklist. Pick the register by the nature of the steps, then use the exact marker below. The meaning of each state is identical across registers — only the form differs.

Sequence registerChecklist register
Use for Ordered steps you move through in turn — phase plans, wizards, la-stepper, la-step-ring Unordered sub-tasks inside one step — they needn't be done in order
Marker Numbered circle (22px), monochrome Check-circle icon (~20px)
Hierarchy Weight + grey scale — never colour for done / active / pending Green reserved for completion; otherwise grey

Why hybrid: a sequence carries meaning through position + number, so it stays calm and monochrome (matching the "hierarchy through grey, never colour" rule and la-stepper). A checklist has no position, so a green completion check is the clearest affordance — and green stays reserved for exactly that. Colour appears only for genuine exceptions (attention / processing), never for ordinary progress.

The states

Six states are formalised. "Skipped" is deliberately excluded — bypassed steps read as pending or are dropped from the list.

  • complete / done — finished.
  • active — in progress, where you are now.
  • pending / to-do — not started, but available.
  • gated — locked until a prior gate clears.
  • attention — overdue, failed, or needs action.
  • processing — async work underway (upload, sync, AI run).

Radial — la-step-ring

The ring is a sequence progress overview, so it follows the sequence semantics through segment fills: complete → primary, active → primary at 0.5 opacity, pending → muted. Per-segment gated / attention are not shown in the ring — it shows progress, not per-step exceptions; surface those in the accompanying list.

Future home

These markers currently live as page-scoped CSS (.phase-row .pn, .ov-substep) plus shared classes. When a second non-RIF consumer appears, promote them to a la-step-marker primitive (variant="sequence | check", status, index) so the mapping is enforced in one place rather than re-declared per surface. Until then, this page is the contract — match it exactly.
