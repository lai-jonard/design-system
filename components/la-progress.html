la-progress

A determinate progress bar: one continuous fill for how far a known quantity has got, such as the steps of a run, the items of a batch or the bytes of an upload. Neutral by default: an ink fill on a muted track, both with pill ends. variant colours it for how an operation ended or stands, always with words beside it that say the same; the value never changes the colour. A sequence of named steps is la-stepper, a radial overview is la-step-ring, and a wait of unknown length is la-spinner. la-progress says how much, not which step.

Anatomy

  1. Track. The whole bar: full width of its container, pill ends, the muted colour. It carries the bar’s role, name and value for screen readers.
  2. Fill. How far it has got, from the left: ink, or the colour of its variant. A full-width pill slid in from the left, so its leading end stays round at any value.

la-progress

A determinate progress bar: one continuous fill for how far a known quantity has got, such as the steps of a run, the items of a batch or the bytes of an upload. Neutral by default: an ink fill on a muted track, both with pill ends. variant colours it for how an operation ended or stands, always with words beside it that say the same; the value never changes the colour. A sequence of named steps is la-stepper, a radial overview is la-step-ring, and a wait of unknown length is la-spinner. la-progress says how much, not which step.

Properties

PropertyAttributeTypeDefaultDescription
value value number 0 how far it has got, from 0 to max; clamped, and 0 when not a number
max max number 100 the whole (default 100); a step count when the value is steps; 100 when not above 0
label label string 'Progress' accessible name (default "Progress"); "" makes the bar decorative
valueText value-text string | undefined — the value in words for assistive tech, such as "2 of 10 steps" (attribute value-text)
size size ProgressSize 'default' default (4px, beside a label in a row) · lg (6px, heading its own panel); --la-progress-height(-lg)
variant variant ProgressVariant 'neutral' neutral (default) · success · warning · danger; set by the page, never by the value

CSS tokens

TokenUsed for
--la-progress-height · --la-progress-height-lgThe track’s height: 4px by default, 6px at lg.
--la-color-bg-mutedThe track.
--la-color-text-secondaryThe neutral fill, the same at every value.
--la-color-successThe success fill.
--la-color-warning-textThe warning fill: the dark amber, as the base amber is 1.97:1 against the track.
--la-color-dangerThe danger fill.
--la-radius-pillThe pill ends of the track; the fill inherits them.
--dur-base · --ease-outThe fill sliding to a new value.

In forced-colours mode the track takes an outline in CanvasText and the fill CanvasText.

Usage examples

A percentage, on the default 0 to 100 scale.

<la-progress value="40"></la-progress>

Steps heading a panel, with the value in the words the page shows.

<la-progress value="2" max="10" label="Plan progress" value-text="2 of 10 steps" size="lg"></la-progress>

Beside a row’s own count: decorative, sized by the page.

<la-progress value="2" max="10" label="" style="width: 96px; flex: none"></la-progress> 2 of 10 steps

An upload that finished, with the words that say so.

<la-progress value="100" variant="success" label="Uploading your articles of association"></la-progress> Uploaded

Notes

  • When to use. How far a known quantity has got: the steps of a run, the items of a batch, the bytes of an upload. Not for named steps the founder moves through (la-stepper), not for a radial overview (la-step-ring), not for a wait of unknown length (la-spinner). la-bandwidth-bar is a capacity gauge and la-distribution-bar splits a total; neither says how far something has got.
  • Colour. Neutral by default, never primary: the fill is the same ink at 100% as at 40%, and --la-color-primary is for interactive elements. variant says how an operation ended or stands, set by the page with words that say the same; the value never sets it. A bar that sums up steps shown on the same screen stays neutral at every value: green marks done on their check markers, as on a playbook run (rule/green-on-a-check; decision 132, and decision 104 as amended 12 Oct 2026). A blocked or overdue run says so once, in the badge or text beside the bar.
  • The words beside it. Prefer a count to a percentage where the count means something (“2 of 10 steps”, loading.md), and pass the same words as value-text. Where the text beside the bar already says the count, and inside a clickable row (a button flattens what it holds), set label="".
  • Width. The bar is block-level and full width. In a flex row, give the host a width, as the modal row does. A page may size and place the host, never paint it.
  • Motion. The fill is a full-width pill slid in with translateX, so its leading end stays round at any value (scaleX would squash it). The first paint draws the value without animating; under prefers-reduced-motion it jumps.
  • Consumers. In this repo, la-run-progress, the head of a playbook run. In new-design, Orion’s playbook modal (05-playbooks.html) and the run’s plan overview (16-playbook-run.html). Still drawn by hand: the UK case plan’s green bar and its copies, onboarding’s Company DNA bar, and la-sidebar’s setup checklist bar. la-upload-box, the first consumer the April spec named, would be the first to use a variant.
  • Against the April spec (loading.md §2.8): an ink fill and a muted track, not primary on a light border, with a variant; max and value-text added; no label or description slots; translateX, not scaleX; and size="lg" for the overview’s 6px.
