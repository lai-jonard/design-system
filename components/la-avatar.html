la-avatar

Photo or initials avatar for people and entities. Given a name it auto-picks a stable photo from the People Avatar Fill set — the same person always gets the same face — so prototype rosters fill with real faces for free. Override the choice with an explicit src or a photo index, or set text-only for legal entities and OpCo codes. Initials are the fallback, shown while a photo loads or if it fails. Four fixed sizes — xs (24 px), sm (32 px), md (40 px), lg (48 px) — map to specific product contexts. Purely presentational: no interactions, no events.

Anatomy

A single circular surface. When a photo resolves it fills the circle (object-fit: cover) over the initials, which sit underneath as the load/failure fallback. Background is --la-color-bg-muted with a 1 px --la-color-border-light border so it reads on both white and off-white surfaces, and frames photos cleanly on white.

la-avatar

Photo or initials avatar for people and entities. Auto-picks a stable photo from a name (override with src or photo), falling back to auto-derived initials. Four fixed sizes (xs/sm/md/lg). Purely presentational.

Properties

PropertyAttributeTypeDefaultDescription
name name string '' Full name; auto-derives initials and the auto photo (e.g. "Ana Reyes")
initials initials string '' Override for auto-derived initials (e.g. "JO")
size size 'xs' | 'sm' | 'md' | 'lg' 'md' 'xs' | 'sm' | 'md' | 'lg'. Default: 'md'
src src string '' Explicit image URL — wins over `photo` and the auto photo
photo photo string | number '' Index 1–88 into the avatar fill set — forces a specific face
textOnly text-only boolean false —
logo logo boolean false Boolean; render `src` as a contained, inset brand mark in a rounded square (not a circle, so a square logo isn't clipped) — the AI assistant
presence presence '' | 'online' | 'away' | 'offline' '' '' | 'online' | 'away' | 'offline'. Renders a corner presence dot (Messenger-style) with a background-coloured ring. Default: '' (none)
assetBase asset-base string '/assets/avatars' —
gender gender '' | 'w' | 'm' | 'woman' | 'man' '' '' | 'w' | 'm' (also 'woman' / 'man'). Constrains the auto from-name photo to one presented gender. Default: '' (any)
FILL_COUNT — number 88 Number of numbered fills available (01–88) in the People Avatar Fill set.
GENDERS — string 'wwwmmmmmmmwmmwmmwwwmmwwmwwmwmmwwmmwwmwmmmmwwwwmmwmmmwwwmwwwmmmmwwwmwmmwmwmwmmwwmmmmmmwmm' Presented gender of each fill, indexed 1–88 (`GENDERS[n-1]`). The fill set encodes this in the filename suffix — `NNw.png` (woman) / `NNm.png` (man) — so a persona's avatar can match their inferred gender (e.g. "Maya Lindqvist" → a `w` fill). Generated from `assets/Avatar/People Avatar Fill/`.
_genderCode — 'w' | 'm' | '' — Normalise the `gender` prop to the 'w' | 'm' filename code, or '' for any.
_imgFailed — boolean false Flips to true if the resolved image fails to load, so we fall back to initials.
_imgLoaded — boolean false Flips to true once the image has loaded, to fade it in.
_displayInitials — string — —
_imageSrc — string — The image URL to render, or '' for initials-only.
text-only — — — Boolean; never show a photo, always render initials (entities)
asset-base — — — Base path for the fill set. Default: '/assets/avatars'

CSS custom properties

No public CSS custom properties. Size and colour are fixed to design-token values for consistency. If you need a non-standard size, use a wrapping element with transform: scale() rather than forking the component.

Usage examples

Auto-derived initials

<la-avatar name="James Okafor"></la-avatar>
<!-- renders "JO" -->

Auto photo from name

<la-avatar name="Ana Reyes"></la-avatar>
<!-- stable photo derived from the name -->

Force a specific photo, or a custom image

<la-avatar name="Mark Hensley" photo="12"></la-avatar>
<la-avatar name="Jon" src="../uploads/jon.png"></la-avatar>

Entity — initials only

<la-avatar initials="HD" text-only></la-avatar>

Brand mark — the LawAdvisor AI assistant

<la-avatar name="LawAdvisor AI" initials="AI"
           src="../assets/brand/logo-mark.svg" logo></la-avatar>

In a detail panel header

<div class="inv-header">
  <la-avatar name="${investor.name}" size="lg"></la-avatar>
  <div class="inv-identity">
    <div class="inv-name">${investor.name}</div>
    <div class="inv-firm">${investor.firm}</div>
  </div>
</div>

Notes

  • Photo resolution: src wins, then photo (an index 1–88 into the People Avatar Fill set), then an auto photo hashed from name. Set text-only to skip photos entirely (legal entities, OpCo codes, teams). The auto photo is deterministic — the same name always maps to the same face.
  • Logo mode: add logo alongside src to render a brand mark — the image is contained and inset, and the avatar switches from a circle to a rounded square so a square logo isn't clipped at the corners. Used for the LawAdvisor AI assistant (the mark, never a stock face); keep initials="AI" as the fallback. The square/circle split doubles as a quiet system-vs-person cue.
  • Stock imagery, fictional people. The fill set is generic stock portraiture. Prototype people and case data remain fictional — the photos give faces to fictional personas, they don't depict real people.
  • Initials derivation: splits on spaces, takes the first character of the first two words. Single-word names produce a single-letter initial. Names with prefixes (e.g. "de la") may produce unexpected results — use the initials override.
  • Fallback: initials sit beneath the photo and show while it loads or if it fails to load (e.g. a broken src), so the avatar never renders empty.
  • Asset path: photos resolve against asset-base (default /assets/avatars), served from the dev/prototype root. Override asset-base if a host serves the fills from a different path.
  • Accessibility: the circle is marked aria-hidden="true" and the photo has an empty alt — it's decorative alongside a visible name. If used standalone (e.g. in a list with no adjacent name text), add an aria-label to the wrapper element.
  • Colour: initials background and border are fixed to token values. Do not override — the neutral palette ensures avatars don't compete with status colours (badges, dots).
