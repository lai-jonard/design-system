la-pdf-preview

Inline PDF preview shared by document review and signing surfaces. It wraps the browser-native PDF viewer rather than introducing a PDF library, and accepts a rendered page image for environments that cannot display PDFs inline.

Anatomy

The host fills its container. A scroll region contains the PDF object; the fallback image or empty state occupies the same region.

Anatomy regions
RegionSourceRole
Scroll region.scrollOwns vertical overflow and allows the preview to fill a constrained page pane.
PDF object<object type="application/pdf">Browser-native renderer. The component appends #toolbar=0&navpanes=0&view=FitH.
Fallback image.fallbackRendered page image used when the browser has no inline PDF viewer.
Empty state.emptyShown when src is empty, or as an open-document fallback when no image is supplied.

la-pdf-preview

Inline PDF preview shared by document review and signing surfaces. Uses the browser-native PDF viewer with a rendered page-image fallback.

Properties

PropertyAttributeTypeDefaultDescription
src src string '' URL of the PDF to display.
fallbackImage fallback-image string '' Image URL shown when the browser has no inline PDF viewer (fallback).
label label string 'Document preview' Accessible label — used as the object's aria-label and the fallback image alt.

Usage examples

<la-pdf-preview
  src="../documents/shareholders-agreement.pdf"
  fallback-image="/previews/shareholders-agreement-page-1.png"
  label="Shareholders' Agreement">
</la-pdf-preview>

Notes

No PDF dependency — the product serves a preview PDF and the browser draws it. Do not add PDF.js or another renderer without a product-level reason.
Always provide a useful label — label becomes the PDF object's accessible name and the fallback image alt text.
Provide a fallback for prototype and automation surfaces — headless browsers and embedded webviews may not load the native PDF plugin. A rendered first-page image keeps the state visually testable.
Mobile uses the rendered fallback — below 768px, the fallback image replaces the embedded PDF object because native viewers are not reliably usable inside a narrow pane.
Processing does not own the preview — hosts such as la-document-page should keep an available PDF visible while analysis runs and communicate processing through status UI.
