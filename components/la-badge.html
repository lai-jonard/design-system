la-badge

A small inline label for status, category, severity, or count. Two types: badge (pill, for status labels) and counter (circle, for numerical counts). Always paired with content — never standalone.

For a status column in a table, the dot appearance drops the pill: a dot in the state's colour, the word, and an optional quieter detail.

Anatomy

Badge is a pill with slotted label content. Counter is a circle with a number.

Expiring soon 3 Blocked
  1. Pill container — badge type. Shared --la-color-bg-subtle surface with a 1px --la-color-border-light border and --la-radius-pill. Variant sets the text colour; primary overrides both bg and border to the solid primary colour.
  2. Label — default slot. A word or short phrase.
  3. Counter circle — counter type. Fixed 20px height, --la-radius-circle, no border. Variant sets the fill; appearance switches between solid (filled) and tinted-surface (ghost).
  4. Dot: badge type, appearance="dot". No pill. A 6px dot in the variant's state colour, the label in --la-color-text-secondary, then detail after a middle dot in --la-color-text-muted. The detail truncates first.

la-badge

A small inline label for status, category, severity, or count. Two types: badge (pill, for status labels) and counter (circle, for numerical counts). Always paired with content — never standalone.

Properties

PropertyAttributeTypeDefaultDescription
variant variant BadgeVariant 'neutral' —
type type BadgeType 'badge' —
appearance appearance BadgeAppearance 'filled' How the variant is painted. `filled` (default) is the shared grey chip, `ghost` a tint with no border for inert status tags, `solid` a full fill. `dot` (badge type only) drops the pill for a status in a table cell: a 6px dot in the variant's colour beside the word, then `detail`.
size size BadgeSize 'default' —
detail detail string '' A quieter second part after the word and a middle dot, such as "2 of 10 steps" or "Waiting on HMRC". Read by the `dot` appearance only. In a narrow cell it truncates with an ellipsis; the word never does.

Usage examples

Status label — urgent

<la-badge variant="danger"> Action required </la-badge>

Category label

<la-badge variant="accent"> Doc Quality </la-badge>

With icon — fill weight only

<la-badge variant="warning"> <i slot="icon" class="ph-fill ph-warning-circle"></i> Expiring </la-badge>

Counter — filled (unread count)

<la-badge type="counter" variant="primary"> 12 </la-badge>

Counter — ghost (subtle indicator)

<la-badge type="counter" variant="neutral" appearance="ghost"> 3 </la-badge>

Counter — danger (urgent count)

<la-badge type="counter" variant="danger"> 5 </la-badge>

Dot: a status in a table cell, with its detail

<la-badge appearance="dot" variant="warning" detail="2 of 10 steps"> In progress </la-badge>

Dot with its tip: la-tooltip opens it, tabindex lets the keyboard reach it

<la-tooltip appearance="light" max-width="280px" tip="HMRC usually agrees a share valuation within 30 days, and you can set the scheme rules meanwhile."> <la-badge appearance="dot" variant="danger" detail="Waiting on HMRC" tabindex="0"> Blocked </la-badge> </la-tooltip>

Notes

Badge is always paired with content, never standalone — a badge outside of a containing row, card, or title loses its meaning. The surrounding content is what it's labelling.
Counter is a numerical count signal — use it for unread item counts, queue depths, and notification totals. For single-digit counts it renders as a perfect circle; for two or more digits the width grows to accommodate the number.
Variant names carry accessible context — colour alone fails a11y. The semantic variant name (danger, warning, etc.) pairs with the colour so meaning is not colour-only. Logged in design-language/components.md known divergences.
accent is a category, not a status — use it for classification labels like "Doc Quality", "Legal Compliance". The other variants carry status or prominence meaning; accent carries domain meaning. Not applicable to counter type.
Ghost appearance is for deemphasised counters — ghost uses the faint tinted surface for the variant colour rather than a solid fill, giving a softer presence. Use it when the count should not dominate the surrounding UI. Use filled (default) when the count is a primary signal such as an unread inbox badge.
Icons use Phosphor fill weight — when slotting an icon on a badge, always use ph-fill, never the outline ph class. The filled glyph matches the badge's solid tinted surface.
Dot is for a status column. Use appearance="dot" where a table or list gives every row a status, as Your playbooks does in new-design: a pill on every row is chrome. A status that stands alone, in a header or on a card, stays a ghost badge (rule/ghost-status-badges). One concept takes one appearance on a surface (rule/consistent-status-treatment).
The variant follows the state. Take it from the paired-badge table in status-conventions.md: Complete is success, In progress warning, Not started neutral, Overdue danger. Blocked is not in that table; it is danger, like Overdue (decided 2 October 2026). The dot takes the state's colour and the word stays in ink, so the state is said once in colour and always in words. accent and primary are not states and draw the neutral dot.
The detail says how far, or who it is waiting on. detail is plain text after a middle dot: a count ("2 of 10 steps") or the party the run waits on ("Waiting on HMRC"). It truncates with an ellipsis in a narrow cell; the word never does. There is no icon: the dot is the glyph, so the icon slot is not drawn. detail is read by the dot appearance only.
A tip is la-tooltip's job. Wrap the badge in la-tooltip appearance="light" and give the badge tabindex="0", with no wrapper element: the badge draws the focus ring, and the tooltip opens on focus as it does on hover. In a narrow cell give the la-tooltip host max-width: 100% so the badge inside can shrink. la-tooltip does not yet wire aria-describedby, so a screen reader hears the status but not the tip: put in the tip what helps, never what is needed.
