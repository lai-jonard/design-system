la-run-overview

Where a playbook run has got, in its header: a pill with the section you’re in and the count, which opens the playbook overview. The overview heads with la-run-progress, then lists each section with its own count and every step under it, with the card’s numbered marker. Picking a section or a step takes the page to it. The count stays on the pill, so the overview is never the only place a founder can see how far they’ve got. It opens in the top layer, placed against the pill, and focus moves into it (decision 143).

Anatomy

  1. Pill. The section you’re in, numbered (“02 Prepare and sign”), a hairline, the count (“3 of 10 steps done”) and a caret. It’s a button named by its own text. A section name too long for it is cut, and shown whole in a tooltip on hover and focus.
  2. Heading. “Playbook overview”, which names the popover, a non-modal dialog in the top layer.
  3. Progress. la-run-progress: the count, then the bar, named for the run (run-title).
  4. Sections. Each with la-step-marker’s check (done, in progress, not yet started), its name and its own count (“2 of 2”).
  5. Steps. Under each section, the card’s numbered la-step-marker and the step’s title, wrapped at 12px. The step you’re on reads heavier and is marked as current.

la-run-overview

Where a playbook run has got, in its header: a pill with the section you’re in and the count, which opens the playbook overview. The overview heads with la-run-progress, then lists each section with its own count and every step under it, with the card’s numbered marker. Picking a section or a step takes the page to it. The count stays on the pill, so the overview is never the only place a founder can see how far they’ve got. It opens in the top layer, placed against the pill, and focus moves into it (decision 143).

Properties

PropertyAttributeTypeDefaultDescription
sections sections RunSection[] [] one {name, steps?} or {name, done, total} per section, in run order (attribute: JSON)
heading heading string 'Playbook overview' the popover's heading and accessible name (default "Playbook overview")
runTitle run-title string '' attribute run-title: the run's title, the name of the bar it draws (decision 148); without one the bar is "Playbook progress"
open open boolean false whether the overview is open; the founder's clicks set it, and a page may set it (reflected)

Events

EventTypeDescription
la-run-overview-toggle CustomEvent {open}: when the founder opens or closes it (not when the page sets `open`)
la-section-select CustomEvent {index}: the section picked, for the page to open and scroll to
la-step-select CustomEvent {section, step, number}: the step picked (indexes, and its number in the run)

Usage examples

The run’s sections and steps, as a property.

<la-run-overview run-title="Appoint a director" .sections=${[{name: 'Check', steps: [{title: 'Check your articles…', status: 'complete'}, …]}, …]}></la-run-overview>

Counts only, as JSON in the attribute.

<la-run-overview sections='[{"name":"Check","done":2,"total":2},{"name":"File","done":0,"total":4}]'></la-run-overview>

Taking the page to what was picked: open the section if it’s folded, scroll, and put focus there.

overview.addEventListener('la-step-select', (e) => showStep(e.detail.section, e.detail.step));

Notes

  • When to use. The header of a playbook run. Not for a list of runs, where each row carries la-progress.
  • The data, and a method. sections is one {name, steps?, done?, total?} per section, in run order. With steps ({title, status}, status complete · active · pending · passed) the counts come from them; without, done is kept between 0 and total. JSON as an attribute. Without run-title the bar is “Playbook progress”. A run with no steps isn’t drawn. close() closes it from the page.
  • Where you are. The section on the pill is the first one not finished, because steps run in order; when all are done it shows the last. With steps given, the step you’re on is the one marked active.
  • What counts. A step counts once it settles: done, moved past, or done before you started. Moved past counts as done (RP1, Jonard, 13 Oct).
  • Focus. A panel you work in, so a non-modal dialog (decision 143): when the founder opens it, focus moves to its first section (to the panel itself when there are none). It isn’t trapped. Escape closes it and returns focus to the pill; a click outside closes it. One is open at a time. Opened by the page, it leaves focus where it was.
  • Where it opens. In the top layer (the popover attribute), right after the pill in the page, so no container clips it and reading order holds. CSS anchor positioning puts it below the pill and flips it to fit; where the browser lacks it, the component places it from the pill, moves it as the page scrolls or resizes, and keeps it inside the window (decision 143, rule/pop-outs-never-clip), as la-sources does.
  • What it leaves out. Orion’s north-star pill carried a status word, an owner and dates. Phase B has neither an owner nor dates, and no system puts a status word on a trigger (Jonard, 12 Oct 2026).
  • Against Bobby’s CMS. 07 draws the count and bar on a line under the run’s intro. Here the count lives on the pill and the bar in the popover; the page doesn’t also show the line (RP2 closed 14 Oct, A, decision 148).
  • Closed 14 Oct, built 14 Oct (decisions 148 and 143). The counts (RO2, amended 14 Oct): the pill says “3 of 10 steps done”, as the bar it opens; the page’s section headings keep “done”, the rows a bare count. A long section name is cut on the pill and shown whole in an la-tooltip on hover and focus (RO3, C). A long list scrolls past min(70vh, 560px), the heading and bar staying put (RO4, A). The bar is named for the run (RP3). The popover opens in the top layer, and focus moves in (X6).
